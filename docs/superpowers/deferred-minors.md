# ข้อย่อยจากการรีวิวที่ยังไม่ได้แก้

รวบรวมจากการรีวิวโค้ดทุกรอบใน branch `fix/mbot2-collective-decision-making` เมื่อวันที่ 2026-10-30

- ไม่มีข้อไหนที่ทำให้หุ่นค้างในซิมรอบล่าสุด
- ส่วนใหญ่เป็นกรณีขอบ หรือเรื่องความเรียบร้อยของโค้ด
- ใช้รายการนี้ตอนเลือกว่าจะเก็บงานข้อไหนต่อ

## การตรวจแยกและแผนที่ร่วม (แยกดำ, ค1)
- **ระยะกันสะดุดซ้ำสั้นกว่าที่ตั้งใจ:** หลังออกจากแยก หุ่นต้องเดินให้ครบระยะก่อนจะนับสะดุดเส้นครั้งใหม่ แต่ระยะนี้นับรวมระยะที่ตัวหุ่นเหวี่ยงตอนหมุนอยู่กับที่ด้วย จึงสั้นกว่าที่ตั้งใจประมาณ 6 ซม.
- **ทิศกิ่งที่ส่งให้ทีมเป็นมุมที่วัดได้จริง** ไม่ได้ปัดเป็น h0 ± 90° ตามที่ spec เขียนไว้ ตัวกลางยังจัดเข้าทิศได้ถูก
- **แยกรูปตัว T ที่ขาไปพลาด แล้วมาเจอตอนขากลับจากด้านขาตั้ง:** ทางกลับบ้านถูกเสนอให้ทีมเป็นกิ่งที่ยังไม่สำรวจ
- **log ปนกัน:** ตอนใช้ข้อมูลทีมแทนการหมุนสแกน log ยังขึ้นคำว่า `สแกนแยก` ด้วย ตัวเลขจึงนับซ้ำ
- **มุมกิ่งเพี้ยน:** ถ้ามีกิ่ง 2 กิ่งในแผนที่ตกอยู่ในช่วงมุมเดียวกัน มุมของทั้งสองจะถูกเฉลี่ยรวมกัน
- **จุดชนิดอื่นถูกรวมเข้ากับจุด `DEAD_END`** ที่อยู่ในรัศมี
  - แก้แล้วเฉพาะ `START` กับ `GOAL` ซึ่งไม่ถูกรวมกับจุดอื่นอีก
- **บันทึกทางตันเกินจำเป็น:** ทางตันที่เจอกำแพงขณะเดินย้อนกลับ หรือที่ทางโค้ง ก็ถูกบันทึกเป็น `DEAD_END` ด้วย
- **`link_conflicts` โตขึ้นเรื่อยๆ** ไม่มีขีดจำกัด

## ถามล่วงหน้าและวิ่งผ่านแยก (ค2 ขั้นที่ 1)
- **ข้อมูลฝั่งที่เห็นเส้นค้าง:** ตอนวิ่งผ่านแยกไปตรงๆ ไม่ได้ล้าง `outer_hit_sides` แยกถัดไปจึงอาจหมุนสแกนฝั่งที่ไม่จำเป็น
- **ตำแหน่งแยกคลาด:** ตำแหน่งที่หุ่นจดลงความจำของตัวเองช้าไป 1 tick ทำให้คลาดประมาณ 5 ซม.
- **ไม่มีบันทึกใน `/trail`** ตอนวิ่งผ่านแยก
- **คำขอส่งซ้ำไม่หยุด:** ถ้าเห็นพื้นที่แดงขณะที่คำขอล่วงหน้ายังไม่ได้คำตอบ คำขอนั้นจะถูกส่งซ้ำไปเรื่อยๆ
- **`team_choice` เก่าอาจค้าง** หลังยกเลิกคำขอ (ตอนนี้ยังไม่มีผล)

## ทีมจองงาน (ค2 ขั้นที่ 2)
- **กิ่งของแยกใหม่ยังไม่นับเป็นงาน** ตอนที่หุ่นถามที่แยกนั้นเอง แต่ระบบกลับไปใช้การเลือกแบบปกติได้ถูกต้อง
- **รายการจองค้าง:** หลังเจอเป้าหมาย รายการจองยังค้างอยู่ใน state จนกว่าหุ่นจะส่ง POSE ครั้งถัดไป
- **หุ่นที่กำลังย้อนกลับถูกนับว่าว่าง**
- **`_robot_reach` คิดการกันช่วงทางกลับด้าน**
- **คำนวณซ้ำบ่อย:** คำนวณ Dijkstra ทุกคู่หุ่น–งาน ทุกครั้งที่ได้ POSE แผนที่ขนาดนี้ยังเร็วพอ

## เป้าหมาย (ค3)
- **คำสั่ง `GOAL_ROUTE` ถูกข้ามแบบเงียบๆ** ถ้าหุ่นอยู่ในสถานะอื่น หรือมีเพื่อนอยู่ชิดด้านหลัง
- **กันช่วงทางนานเกินจำเป็น:** การปล่อยกิ่งโดยไม่มีชื่อเพื่อน (ตอนกลับตัวไปเป้าหมาย) กันช่วงทางนั้นไว้เต็ม 60 วินาที
- **`goal_routes` ใช้ระยะเส้นตรง** จากหุ่นถึงจุด ไม่ได้ใช้ระยะตามเส้นทาง

## กลับตัวและเลือกทางไปที่ที่ยังไม่สำรวจ
- **`_graph_distances` เช็ค avoid/BLOCKED ที่ปลายผิดด้านของเส้นเชื่อม**
- **การกันช่วงทางหมดเร็วเกินไป:** ถูกล้างทันทีที่เพื่อนผ่านทางโค้ง 1 จุด
- **การพาไปหาแยกที่ยังมีกิ่งใหม่ไม่เคยเสนอทางที่เพิ่งเดินเข้ามา**
- **`_likely_known` มองไกล 1.0 ม.** ซึ่งเท่ากับ 2 ช่องตาราง อาจเดาผิด
- **ตัดสินไม่ตรงกันชั่วครู่:** `route_order` จาก state ที่เก่าได้ถึง 0.5 วินาที อาจทำให้หุ่นสองตัวตัดสินไม่ตรงกันชั่วครู่ว่าใครต้องกลับตัว
