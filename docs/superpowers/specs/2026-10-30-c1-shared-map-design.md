| ชิ้น | เรื่อง | สถานะ |

## เป้าหมาย
1. ตัวกลางทีมเก็บ**แผนที่ร่วม** ว่ามีจุดอะไรบ้าง และกิ่งไหนของจุดไหนพาไปจุดไหน แผนที่นี้สร้างจากสิ่งที่หุ่นเห็นจริงเท่านั้น ไม่โหลดแผนที่ไว้ล่วงหน้า
2. หุ่นที่ถึงจุดที่ทีมรู้จักแล้ว **ไม่ต้องหมุนสแกนซ้ำ**
3. ตัวกลางทีม**คำนวณเส้นทางสั้นที่สุด**จากจุดใดก็ได้ไปจุดใดก็ได้ ใน ค1 ยังไม่ใช้เส้นทางนี้ขับหุ่น ค2 กับ ค3 จะเป็นคนใช้

**ถือว่าเสร็จเมื่อ:**
- แผนที่ใน `/maze_team/state` หลังจบซิม ตรงกับแผนที่จริงของ `mbot2_seed7_maze` ในส่วนที่หุ่นเดินผ่าน
  - ตรวจด้วยสคริปต์ที่อ่านเส้นจากไฟล์ `.sdf` มาเทียบ สคริปต์นี้ใช้ตรวจอย่างเดียว ไม่ใช่โค้ดของหุ่น
- จุดที่ทีมรู้จักแล้ว หุ่นไม่สแกนซ้ำ ดูจาก log ว่ามี `ใช้ข้อมูลทีม` ขึ้นแทน `สแกนแยก`
- เทสต์หาเส้นทางสั้นที่สุดผ่าน
- ซิมหุ่น 3 ตัว 10 นาที ยังไปถึงเป้าหมายได้ไม่ช้ากว่ารอบล่าสุด ซึ่งเจอเป้าที่ 3:46 และหุ่นครบ 3 ตัวที่ 5:05

**นอกขอบเขต:**
- การมอบงานและคิวกิ่ง (ค2)
- การขับหุ่นตามเส้นทางไปเส้นชัย (ค3)
- การนับลำดับจุดและการรีเซ็ตตำแหน่งสำหรับหุ่นจริง (จดไว้ใน `toRealbot.md`)

## สิ่งที่ตกลงกันแล้ว
- ในซิม ใช้ตำแหน่งจริงจาก Gazebo จับคู่ว่าจุดที่หุ่นเจอคือจุดไหนในแผนที่ (รัศมี `junction_match_radius` = 0.25 ม. เดิม)
- แผนที่เก็บว่า**กิ่งพาไปจุดไหน** โดยไม่ผูกกับพิกัด จึงเอาไปใช้กับหุ่นจริงได้โดยไม่ต้องแก้
- สิ่งที่ต้องทำเมื่อย้ายขึ้นหุ่นจริงให้จดลง `toRealbot.md` เช่น นับลำดับจุดตามเส้นทาง ตรวจตำแหน่งแบบหยาบ และรีเซ็ตตำแหน่งเมื่อถึงจุดที่รู้จัก

## แผนที่ (อยู่ใน `TeamLedger`)
ต่อยอดจาก `self.junctions` เดิม โดยเปลี่ยนจากเก็บเฉพาะแยกเป็นเก็บ "จุด" ทุกชนิด

**จุด (node)** มี `id`, `kind`, `x`, `y`, `branches`

| `kind` | สร้างเมื่อไร |
|---|---|
| `START` | มีจุดเดียว หุ่นส่ง `NODE kind=START` ตอนออกจาก `SEARCH` แล้วเจอเส้นดำ ใช้ตำแหน่งของรายงานแรกเป็นตำแหน่งจุด ส่วนรายงาน `START` ที่ตามมาจะใช้จุดเดิมเสมอ โดยไม่ดูรัศมี เพราะหุ่นแต่ละตัวเจอเส้นห่างกันเกิน 0.25 ม. แต่ละรายงานตั้ง `trail` ของหุ่นตัวนั้นเป็น (START, ทิศที่หุ่นหัน) |
| `JUNCTION` | `BRANCH_REQUEST` เหมือนเดิม |
| `CORNER` | ทางโค้ง หุ่นแจ้งผ่านรายงานใหม่ `NODE` |
| `DEAD_END` | ทางตันจากกำแพงหรือเส้นหมด หุ่นแจ้งผ่าน `NODE` |
| `GOAL` | ตอนหุ่นแจ้ง `GOAL` |

**กิ่ง (branch)** ใช้คีย์ทิศ 4 ทิศเดิม (`direction_key`) และเพิ่ม field:
- `heading`: มุมจริงที่วัดได้ครั้งแรก (หน่วยเรเดียน พิกัดโลก)
- `leads_to`: `{'node': id, 'enter_dir': key}` หรือ `None` ถ้ายังไม่รู้ว่ากิ่งนี้พาไปไหน
  - เมื่อเชื่อมกิ่ง จะบันทึกทั้งสองฝั่ง: กิ่ง `d` ของ A ชี้ไป B และกิ่ง `e` ของ B ชี้กลับมา A

**ทางเดินของหุ่นแต่ละตัว (`trail`):** ตัวกลางจำว่าหุ่นแต่ละตัวออกจากจุดไหนล่าสุด และออกทางกิ่งไหน `(node_id, exit_dir)`
- ทุกครั้งที่หุ่นรายงานว่าถึงจุดใหม่ ตัวกลางจะเชื่อมกิ่ง `trail` เดิมของหุ่นเข้ากับกิ่งขาเข้าของจุดใหม่ โดยกิ่งขาเข้าคือทิศ `approach_heading + π`
- กิ่งขาออกได้มาจาก 3 ทาง:
  1. ทิศที่ตัวกลางเลือกให้ (`BRANCH_REQUEST`)
  2. `exit_heading` ที่หุ่นแจ้งมาใน `NODE`
  3. ทิศกลับรถสำหรับ `DEAD_END` คือทิศ `approach_heading + π`
- **ถ้าข้อมูลขัดกัน** เช่น กิ่งนี้เคยถูกเชื่อมไปจุดอื่นแล้ว ให้เก็บการเชื่อมแรกไว้ ไม่เขียนทับ และเขียน log เตือน
  - กรณีนี้เกิดได้ตอนหุ่นถอยหลีกทางผ่านจุด

**รายงานใหม่ `NODE`** (หุ่น → `/maze_team/report`):
```json
{"type": "NODE", "robot": "mbot1", "kind": "CORNER", "x": 0.75, "y": 0.25,
 "approach_heading": 1.57, "exit_heading": 0.0}
```
- `kind` เป็น `START`, `CORNER` หรือ `DEAD_END`
- `exit_heading` ส่งเฉพาะ `CORNER`

`/maze_team/state` ส่งจุดเหล่านี้ใน field `junctions` เหมือนเดิม แต่เพิ่ม `kind` ในแต่ละจุด และเพิ่ม `heading` กับ `leads_to` ในแต่ละกิ่ง

## หาเส้นทางสั้นที่สุด
`TeamLedger.route(from_node, to_node) -> list[{'node': id, 'exit_dir': key, 'heading': rad}]`
- ใช้ Dijkstra บนเส้นเชื่อมที่รู้แล้ว น้ำหนักของแต่ละเส้นคือระยะตรงระหว่างสองจุด
- ข้ามกิ่งที่เป็น `BLOCKED` และกิ่งที่ยังไม่รู้ปลายทาง
- ถ้าไปไม่ถึง คืนค่า `None`
- ผลที่ได้คือลำดับ "ถึงจุดนี้ ให้ออกทางกิ่งนี้" จนถึงจุดปลายทาง

## ฝั่งหุ่น (`maze_solver.py`, โหมดแยกดำ)
1. **ไม่สแกนจุดที่รู้จักแล้ว**
   - หุ่นจะเช็คเงื่อนไขนี้ตอนตัวนอกเห็นเส้น หรือตอนเส้นหาย
   - ถ้ามีจุดในแผนที่ทีมอยู่ห่างจุดที่เห็นเส้นไม่เกิน 0.25 ม. ให้ถือว่าเป็นจุดนั้น แล้วทำต่อตามชนิดจุด:

   | ชนิดจุด | สิ่งที่หุ่นทำ |
   |---|---|
   | `JUNCTION` | เข้ากลางแยก (ล้ออยู่ที่จุด) แล้วส่ง `BRANCH_REQUEST` เลยโดยไม่หมุน ตัวเลือกคือกิ่งที่ทีมรู้ทั้งหมด ยกเว้นกิ่งขาเข้า ใช้ `heading` ที่บันทึกไว้ |
   | `CORNER` | เข้ากลางแล้วเลี้ยวไปตาม `heading` ของกิ่งขาออกที่บันทึกไว้ แล้วส่ง `NODE` เพื่อให้ `trail` อัปเดต |
   | `DEAD_END` | ทำเหมือนเดิม คือกลับรถ หุ่นจะเลือกเข้ากิ่งที่ตันอยู่แล้วก็ต่อเมื่อไม่มีทางอื่นให้ไป |

   - log ที่ขึ้นแทน `สแกนแยก` คือ `ใช้ข้อมูลทีมที่ J<id>`
2. **แจ้งทีมว่าเจอจุดใหม่**
   - ผลสแกนเป็นทางโค้ง → ส่ง `NODE kind=CORNER`
   - เป็นทางตัน (เจอกำแพง หรือสแกนแล้วไม่มีทางออก) → ส่ง `NODE kind=DEAD_END` คู่กับ `BLOCKED` เดิม
3. **ตำแหน่งที่หุ่นรายงาน** ใช้จุดหมุนของล้อตอนสแกน (`scan_pivot`) แปลงเป็นพิกัดโลก
   - ถ้าเป็นจุดที่รู้จักแล้ว ใช้ตำแหน่งที่บันทึกไว้เดิม ไม่อัปเดตตามตำแหน่งที่วัดใหม่
4. **ถ้าข้อมูลทีมขาดหาย** (`/maze_team/state` เก่าเกินหรือไม่มี) ให้สแกนตามปกติ

## ความเสี่ยง
- **จับคู่จุดผิด:** ถ้าจุดสองจุดอยู่ใกล้กันไม่เกิน 0.25 ม. หุ่นอาจจับคู่ผิด ใน seed7 จุดห่างกันอย่างน้อย 0.5 ม. แต่ทางโค้งที่ติดแยกอาจอยู่ใกล้กว่านั้น ซิมต้องรายงานถ้าพบกรณีนี้
- **แผนที่ทีมผิด หุ่นก็ผิดตาม:** ถ้าการสแกนครั้งแรกพลาดกิ่งไป หุ่นตัวหลังที่ไม่สแกนซ้ำจะไม่เห็นกิ่งนั้นเลย ใน ค1 ยอมรับข้อนี้ไว้ก่อน แล้วจดเป็นเรื่องที่ต้องพิจารณาใน ค2
- **การถอยหลีกทางทำให้ `trail` เพี้ยน:** ตามที่เขียนไว้ด้านบน ระบบจะเก็บการเชื่อมแรกไว้และเตือนใน log
- **ซิมช้ากว่าเวลาจริง:** เกณฑ์เวลา "ไม่ช้ากว่ารอบล่าสุด" จึงคลาดเคลื่อนได้ราว ±30 วินาที
