# ทดลอง mBot2 แบบ 2–3 ตัวที่สื่อสารกัน

## สิ่งที่ทำงานร่วมกัน

- `maze_solver` ของแต่ละตัวอ่าน RGB, ultrasonic และ odom ของตัวเอง ไม่แชร์คำสั่งมอเตอร์กัน
- `team_coordinator` รับรายงานผ่าน `/maze_team/report` และตอบการจองกิ่งผ่าน `/maze_team/decision`
- ก่อนเจอเป้าหมาย ตัวกลางให้หุ่นคนละกิ่งถ้ามีทางว่าง เมื่อกิ่งตันจะไม่ส่งตัวอื่นเข้ากิ่งนั้นอีก
- เมื่อหุ่นตัวใดเห็นสีเขียว จะส่ง `GOAL` ผ่าน `/maze_team/report`; ตัวกลางเผยพิกัดนั้นใน `/maze_team/state` และเลือกกิ่งที่มุ่งไปทางเป้าหมายให้ตัวอื่น
- ตำแหน่งและสถานะเพื่อนที่แชร์กันช่วยแยก “หุ่นขวางหน้า” ออกจาก “กำแพง”: หุ่นขาไปถอยหลีกทางสั้น ๆ ให้หุ่นขากลับออกจากแยกก่อน แล้วจึงทำงานต่อ โดยไม่บันทึกกิ่งเป็นทางตัน
- การเลี้ยวใช้พิกัดแยกเดียวกันที่ทีมบันทึกไว้เพื่อขยับตัวรถให้ถึงจุดตัดก่อนหมุน ลดการเลี้ยวเร็วเกินไปเพราะกล้องเห็นสีเหลือง/ขอบเส้น
- หลังเลี้ยวจะเดินตามแกนกิ่งที่เลือกก่อน หาก RGB ยังไม่เห็นดำจะกวาดซ้าย–ขวาไปตามกิ่งแทนการหมุนอยู่กับที่บนเส้นเก่า
- เมื่อตามเส้นแล้วสองเซนเซอร์ในอยู่บนดำ รถใช้ความเร็วปกติ; ถ้าเส้นอยู่ข้างเดียวจะชะลอและหักเลี้ยวมากขึ้น
- เมื่อถึงปลายทาง รถที่พบสีเขียวหยุดตรงเป้าหมาย รถที่ตามมาอาจหยุดต่อท้ายเพื่อนในเขตรวมพล (ไม่ต้องเบียดให้ RGB แตะสีเขียวทุกคัน)

## แผนที่ร่วมของทีม (ค1)

- `TeamLedger.junctions` เก็บทุก "จุด" ที่หุ่นเห็นจริง ไม่ได้โหลดแผนที่ล่วงหน้า แต่ละจุดมี `kind` เป็น `START`, `JUNCTION`, `CORNER`, `DEAD_END` หรือ `GOAL`
  - มี `START` เพียงจุดเดียวเสมอ
  - ทางโค้งที่ภายหลังพบว่ามีกิ่งที่สามจะเปลี่ยนเป็น `JUNCTION` และจะไม่เปลี่ยนกลับ
- แต่ละกิ่ง (คีย์ทิศ 4 ทิศเหมือนเดิม) มี field เพิ่ม 2 ตัว:
  - `heading`: มุมจริงที่วัดได้ครั้งแรก
  - `leads_to`: `{'node': id, 'enter_dir': key}` บอกว่ากิ่งนี้พาไปจุดไหน และเข้าจุดนั้นทางกิ่งไหน
- ตัวกลางจำว่าหุ่นแต่ละตัวออกจากจุดไหนล่าสุด ทางกิ่งไหน (`trails`) แล้วเชื่อมกิ่งนั้นกับจุดถัดไปที่หุ่นรายงาน
  - ถ้าการเชื่อมใหม่ขัดกับที่บันทึกไว้แล้ว (เช่น ตอนหุ่นถอยหลีกทางผ่านจุด) จะเก็บการเชื่อมเดิมไว้และเขียน log `map link ignored`
- หุ่นส่งรายงาน `NODE` ไปที่ `/maze_team/report` ตอนออกจากกล่องเริ่ม (`START`), ตอนเลี้ยวทางโค้ง (`CORNER`, มี `exit_heading`) และตอนเจอทางตัน (`DEAD_END`) ส่วนแยกยังใช้ `BRANCH_REQUEST` เหมือนเดิม
- `TeamLedger.route(from_node, to_node)` หาเส้นทางสั้นที่สุดบนกิ่งที่รู้ปลายทางแล้ว โดยข้ามกิ่ง `BLOCKED` และคืนค่าเป็นลำดับ "ถึงจุดนี้ ออกทางกิ่งนี้" (ค2 กับ ค3 จะเป็นตัวใช้เส้นทางนี้)
- ในโหมดแยกดำ ถ้าจุดที่หุ่นถึงอยู่ในแผนที่ทีมแล้ว (ห่างไม่เกิน 0.25 ม. และข้อมูลทีมใหม่กว่า 1 วินาที) หุ่นจะใช้กิ่งที่ทีมบันทึกไว้แทนการหมุนสแกน ใน log จะขึ้น `ใช้ข้อมูลทีมที่ J<id>`
 ตัวควบคุมอ่านพิกัดจริงของหุ่นจาก `/world/simple_branch_maze/dynamic_pose/info` เพราะ `odom` จากล้อคลาดได้มากหลังเลี้ยว ทำให้ทั้งการจองแยกและการจัดแนวผิดได้ การใช้พิกัดจริงเป็นเพียง **ระบบระบุตำแหน่งของซิม ไม่ใช่การให้แผนที่ล่วงหน้า**; หุ่นจริงต้องแทนส่วนนี้ด้วยการระบุตำแหน่งในกรอบร่วม (เช่น SLAM หรือ marker localization) และไม่สามารถใช้ Gazebo ground truth ได้

## เปิดการทดลอง

```bash
cd ~/ros2_ws
source /opt/ros/humble/setup.bash
colcon build --packages-select mbot2_control mbot2_description
source install/setup.bash
ros2 launch mbot2_description two_mbot2.launch.py robot_count:=2
```

เปลี่ยนเป็น `robot_count:=3` สำหรับสามตัว ตัวควบคุมเริ่มห่างกัน 8 วินาทีต่อคันเพื่อลดการชนบนทางเริ่มต้น หากต้องการเปิดเฉพาะ Gazebo ใช้ `start_controllers:=false`
ถ้าต้องการรันโดยไม่เปิดหน้าต่าง 3D เพิ่ม `headless:=true`

เปิดอีกเทอร์มินัลเพื่อตรวจข้อความที่มีผลต่อการตัดสินใจ:

```bash
source /opt/ros/humble/setup.bash
source ~/ros2_ws/install/setup.bash
ros2 topic echo /maze_team/decision
ros2 topic echo /maze_team/state
ros2 topic echo /maze_team/report
ros2 topic echo /mbot1/trail
```

ตัวอย่างที่ควรเห็น: ที่แยกเดียวกัน `mbot1` ได้ `straight` และ `mbot2` ได้ `left` เมื่อทั้งสองถึงแยกนั้นจริง หากตัวใดเจอกำแพง กิ่งที่ตัวนั้นจองจะเปลี่ยนเป็น `BLOCKED` ใน state ของทีม

## ขอบเขตและสิ่งที่ต้องทดสอบใน Gazebo

- การระบุ “แยกเดียวกัน” ใช้ระยะไม่เกินพารามิเตอร์ `junction_match_radius` ของ `team_coordinator` (ค่าเริ่มต้น 1.00 เมตร สำหรับ `simple_branch_maze` ที่แยกห่างกันอย่างน้อย 3 เมตร เพราะกล้อง 1 พิกเซลอาจจับกิ่งช้ากว่าจุดตัดจริง); `two_mbot2.launch.py` ตั้งเป็น 0.25 เมตร เพราะ `mbot2_seed7_maze` มีแยกห่างกันเพียง 0.5 เมตร; ทิศกิ่งแบ่งแบบ 90° เหมาะกับ `simple_branch_maze.sdf` ไม่ใช่ SLAM ทั่วไป
- หัวข้อพิกัดจริงเป็นของโลก `simple_branch_maze` หากเปลี่ยน world ต้องแก้ชื่อ topic ใน launch และตัวควบคุมด้วย
- การประกาศเป้าหมายไม่ใช่ global path planner: ตัวกลางเลือกกิ่งที่หันเข้าใกล้เป้าหมายและหลบกิ่งที่ทราบว่าตัน แต่เขาวงกตซับซ้อนอาจต้องสร้างกราฟเส้นทางและหา shortest path
- ถ้าตัวกลางไม่ทำงาน หุ่นจะหยุดรอคำตอบที่ทางแยก แทนการเดาทางเอง
- ผลทดสอบ Gazebo แบบ headless บน WSL: 2 ตัวแบ่งกิ่ง J1/J2, หลบกันบนเส้นทางแคบ และ `mbot2` พบสีเขียวพร้อมส่ง `GOAL` ถึงตัวกลาง; รอบ 3 ตัว `mbot2` พบสีเขียว, `mbot1` จอดตามข้อมูลทีมที่ระยะ 0.68 ม. และ `mbot3` จอดต่อท้ายในเขตรวมพลที่ระยะ 1.35 ม. จากเป้าหมาย ทั้งสามเข้าสถานะ `GOAL_REACHED` ในการทดสอบหนึ่งรอบ ไม่ได้หมายความว่ากล้อง RGB ทั้งสามเห็นสีเขียว
- ข้อจำกัด: การหลีกทางแบบถอยสั้นยังไม่มีเซนเซอร์หลังจริง; ตัวที่ตามอาจรอเมื่อมีรถหลายคันขวางกันบนเส้นแคบ และการกลับไปหาเป้าหมายเป็นการเลือกกิ่งจากทิศทาง ไม่ใช่ shortest-path planner บนกราฟเต็ม
- การทดสอบบน WSL เครื่องนี้ต้องใช้ `LIBGL_ALWAYS_SOFTWARE=1` ในโหมด headless มิฉะนั้น `ogre2` อาจหยุดด้วยข้อผิดพลาด OpenGL
